# 人类反馈与处理记录

记录日期：2026-11-11。范围为 DCL 的总控台应用实验。用户原话与 Agent 解释分别记录；日期是本次记录日，没有精确消息永久链接，不编造用户测试条件。

## FB-DCL-01：研究需要成为可复用资产

**用户原话（当前会话）：**

> 继续扩大对于案例的分析和研究 使其能够沉淀为可复用的规范资产 如果只是研究一些案例 很容易过拟合 变成每一版小样都是已经研究过的案例的翻版 同时及时审查/复盘之前的产出

**Agent 编码：** 研究产出的可复用性、来源偏差、原创性和持续复盘。用户要求扩大研究，没有指定案例数量、固定界面样式或通用设计系统。

**处理要求：** 保留原有终末地研究及证据边界；加入不同产品／任务机制的对照与反例；将候选原则整理成可执行但仍有状态标识的规范资产。每条规范说明问题、适用条件、可调整部分、禁止误用、来源和检查方法。增加脱离原案例重新推导的验证，不能靠换一个参考产品继续照搬。

**验证状态：** 原话已记录；跨产品研究与规范资产由本轮工作形成后从项目入口登记。是否解决过拟合仍需看新情境的实际结果，不能以新增文档数量判定。

## FB-DCL-02：克制不等于单调

**用户原话（当前会话）：**

> 对于当前小样的意见：界面过于单调 层次感虽然需要克制设计，避免繁杂 但不代表我们应该完全的单调化

**对象：** 当前 A—F 六种局部小样的总体视觉体验；用户未指定其中某一张截图、区域、主题或屏宽。

**Agent 编码：** 视觉表达与层次不足。不能把这条反馈推断成用户要求高饱和、多阴影、多图案或某一种固定美术方案。

**Agent 分析：** 旧六版虽然改变信息结构，却共享浅纸色、细线、相似字号、切角按钮及大面积同质表面；对象、原因、背景和动作的视觉职责区分不充分。布局差异没有充分转化为视觉重心、节奏及空间层次差异。见[第二轮复盘](../../docs/review-02.md)。

**处理要求：** 用工作内容决定层次，尝试空间嵌套、深浅表面、字体尺度、状态图形和有限材质，并记录各自承担的意义。保留旧版作基线；新增设计同时检查信息正确性、主次辨认和装饰代价。不同美术表达允许共享正确的业务语义，不要求为了“不同”修改事实。

**验证状态：** 这是用户明确的负面反馈，当前应登记为待解决；此前 Agent 的视觉判断不构成验收。新实验的自动检查只能证明所测条件，仍需用户审阅视觉改进。

## 旧结论如何接续

此前“倾向 A 日常入口＋D 原因解释”是 Agent 的候选建议，用户没有认可这一组合。当前将其保留为可检验的结构假设，暂停将其当作优选方向；在新视觉及多数据情境比较完成后再判断。旧报告不删除，后续结果通过新版本与复盘链接接续。

**下次反馈定位方法：** 若后续有具体使用困难，记录方案／数据情境／屏宽／对象／触发／实际与期望结果；没有这些信息时保留总体意见，不替用户补造细节。
