# 第二轮实验：从单调反馈到有条件的层次

2026-11-11。用户负面反馈见[原话](../human-feedback.md)，基线问题见[复盘](../../../docs/review-02.md)。本轮 Agent 判断与自动检查分开，没有真人审美分数或完成率。

## 比较的变化与职责

| 表达轴 | A—F 基线 | G 工作台 | H 研判页 |
| --- | --- | --- | --- |
| 空间 | 多数区靠细边线划分 | 环境、内凹列表、当前工作面 | 平面档案＋深色原目标摘要 |
| 文字节奏 | 多数内容尺度相近 | 目标／当前对象／原因／元数据分级 | 衬线任务标题与有序原因形成阅读节奏 |
| 色彩 | 相近纸灰与单一强调 | 冷色面、操作色与状态色分工 | 暖纸色、褐色动作与独立完成标记 |
| 内容图形 | 依赖图仅部分方案使用 | 满足比例由真实样例计算 | 同一比例＋编号清单；摘要明确为预期产物 |
| 材质 | 很少 | 局部网格提示工作背景 | 局部斜纹与纸面边缘；正文区保持清楚 |

G 仍使用清单＋详情的熟悉结构，但没有因此计为独立新结构；H 也不因衬线和纸色计作新的交互机制。本轮重点是规范是否允许不同表达，并保留正确语义。

## 实际判断

G 的焦点面比基线突出，操作与前置状态更容易在截图中区分；任务清单与主对象仍有重复。H 的阅读节奏和原目标提示更强，主动作强度较低；标题、原任务摘要重复会拉长内容。两者手机均有较大纵向成本，特别是 H 的说明侧栏移到后方。因此不判定哪种胜出，也不恢复旧 A+D 的优选地位。

纹理关闭后信息文本完全一致。这只说明纹理未承担必要语义；审美贡献需要人判断。删除纹理不等于删除明暗层、字形差异或内容图形，所以不能把这一检查写成“所有层次都无用／都有效”。

## 实现冻结与新情境

实现于 `9345d42` 冻结，之后只在 extra-cases.js 加入“资料发布核对”的不同领域措辞、共享前置、长标题与特殊字符。最终检查中四个实现文件哈希与冻结值相同，新增数据无需改布局或导航。设计者知道测试方法，也有既有案例上下文，这不是盲实验或独立产品验证。

留出情境也暴露了边界：[实际读取项目下拉的记录](../../../runs/review-02/heldout-boundary.json)显示仍固定为首轮的两个项目；新“publishing”情境能在全部范围排查，但不能在下拉中单独选该项目。现阶段只证明其对象／依赖内容适应，不证明项目选择器已通用化。此限制应在后续采用前修正并另建验证记录，不能因主路径通过而略去。

逐来源排除推导：没有终末地理由时，方向由 GitHub 与真实 deps 支持，分组／依赖的区别由 Blender 支持，返回与确认边界由 GOV.UK 支持；没有 Carbon 时，Atlassian／Material 仍提供其他层次手段。移除全部外部体系后，真实边、原对象和反馈处理仍是项目约定，具体色值／造型则没有必须保留的依据。这是理由审查，不是测得的因果贡献。

## 检查结果与失败

[最终记录](../../../runs/review-02/layers-final/verification.json)：两种表达各检查六个既定情境和一个新情境；16组屏宽／主题布局组合；导航与返回、缺失、循环、空结果、键盘焦点、主要按钮44px项目目标、减少动态效果、直接离线打开和去纹理内容一致性通过。[规范检查](../../../runs/review-02/spec-asset-check.json)验证9条卡片引用、CSS生成一致性与32组指定配色对比；不是整页WCAG认证。

首轮发现 H 原任务选择器375px横向溢出，已在冻结前修正。后续按钮尺寸测量有一次偶发失败，记录未捕获到实际尺寸，不能据此认定根因；脚本现等待当前动画结束后测量，最终复查通过。初期全页截图受到先前滚动位置和焦点影响，已改为回到页顶、清除截图焦点并重新加载手机入口，最终截图从正确初态生成。旧 first-look 与初轮记录保留，不冒充最终状态。

尚未验证：真人辨认主次的速度与偏好、完整键盘／屏幕阅读器流程、大规模数据、真实写入事务、跨产品成功迁移。规范中的视觉条目继续为候选，用户反馈状态保持待审阅。
