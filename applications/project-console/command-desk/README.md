## 为什么重做

用户对旧工作台的直接反馈是：界面太过单薄、缺乏空间感和层次感、状态转换的引导不明确。旧工作台在既有三栏结构上连续改稿，信息正确，但每个区域权重相近，纸面、队列、状态面板都在同一个平面上。

这一版不沿旧工作台的结构重构。产品对象沿用总控台的 Project / Task / Note 与规划里的六条流程；视觉和交互重新组织为一张「桌面」：底层是项目场，往上依次是项目带、任务签、任务纸面，最上层是状态仪器。DCL 的研究与守卫方法选择性复用，旧的布局、组件和视觉节奏不复用。

## 三个主张

1. **一张被推到眼前的纸。** 当前任务是唯一的大面积纸面，标题、预期产出、进入条件、结果与记录都在上面。队列是压在纸下的标签，控制台是压在纸右边的仪器；三者用重叠、遮挡和投影建立前后关系，而不是并排三等分。
2. **状态是一台仪器，不是一句提示。** 右侧固定显示 00 承诺 → 01 待开始 → 02 进行中 → 03 已完成 的阶梯，阶梯之间标出闸门；主按钮永远写着目标状态，下面写「为什么」，再下面写「提交后」的影响。
3. **承诺与执行分开。** 想法／暂定方向先停在 00；承诺之后才进入前置检查。前置未满足、人工阻塞、完成记录冲突分别有不同形状和文案，不用一个颜色承担全部语义。

## 空间与层次

| 层 | 内容 | 深度手段 |
| --- | --- | --- |
| 底层 | 深墨场地、网格、同心轨道、坐标 | 固定背景、低对比、边缘渐隐 |
| 第一层 | 五个项目区，按优先级横排 | 卡片浮起 2px，当前项目加宽 1.35 倍、抬升 5px、顶部酸黄细线 |
| 第二层 | 任务队列，本周／全部的范围与状态筛选 | 深色签条压在纸下；当前签右移 8px 并压入纸面 24px |
| 第三层 | 任务纸面 | 暖纸、切角、纸纹、背衬第二张纸偏移 6–12px |
| 第四层 | 状态仪器 | 深墨面板压在纸右缘 24px，下移 58px，内嵌细框与投影 |
| 第五层 | 操作坞、提交单、回执 | 手机上固定在底部；提交单是另一张纸，压暗背景 |

视觉系统：墨色场 #0a0e10、暖纸 #e8e1cf、酸黄 #e2f24d 只用于当前、主要动作和可推进。中文标题用系统黑体 900，编号与英文用 Saira；纸面正文 12–13px，标题 28–41px。浅色主题把场地换成暖灰纸、控制台仍保持墨色，形成「白天桌面 / 仪器」的对照。

## 状态转换怎么读

右侧阶梯是唯一的推进路径说明：

- **00 承诺。** 未承诺的想法停在 00，主操作是「承诺任务」。承诺后才检查前置。
- **00 → 01 的闸门。** 显示「前置 N/N」或「需先承诺」。未满足时主操作不可用，只能查看进入条件或登记人工阻塞。
- **01 待开始。** 前置满足后主操作是「确认开始 → 进行中」。
- **02 进行中。** 主操作是「记录完成 → 已完成」，闸门写明「需填写实际结果」。
- **02 → 03 的完成。** 提交单要求实际结果；提交后回执列出新解锁的任务，记录里保留结果。
- **人工阻塞。** 当前节点变成琥珀色，闸门写「人工阻塞未解除」，主操作「解除阻塞 → 进行中/待开始」；原原因和解除依据写入记录。
- **完成记录冲突。** 上游标为完成但前置未完成时，冲突任务显示斜纹节点，下游列出根因并拒绝推进。

主按钮的目标状态写在按钮内（例如「记录完成 → 已完成」）。按钮下方的「提交后」是模拟结果，不是静态文案：它调用与提交相同的状态函数算出自己会变成什么、哪些任务会新获得可推进资格、哪些会重新等待。提交单再次列出状态变更、当前条件（承诺 / 前置 / 阻塞）和影响，确认后回执复述结果。

进入条件的明细在纸面「进入条件」区：承诺层级、每个前置（可点进去追踪，返回保留原路径与滚动）、人工阻塞。产出区区分预期产出、当前结果、证据索引，未形成时直接写「未形成」「未建立索引」，不补空链接。

## 本周与项目

- 顶部计数只算本周任务（8 项）；队列默认「本周」，切到「全部」才显示 2027 年的算子赛调研（9 项）。
- 项目带按优先级排列，当前项目加宽并标注「当前」；点击项目筛选队列，再点一次取消。当前任务被筛掉时，队列上方给出回到当前的入口。
- 项目简介一直显示在项目带下方，切换项目筛选时同步更新，作为「为什么做这个方向」的上下文。

## 使用

双击 [index.html](index.html) 用 Edge 或 Chromium 打开。离线运行，刷新重置。9 条任务、5 个项目、3 条判断记录都是合成快照，不是线上工作区。

| 操作 | 结果 |
| --- | --- |
| 点任务签 | 打开任务；队列滚动到当前签，纸面与仪器重绘 |
| 点前置「查看」 | 沿真实 deps 下钻；面包屑返回，恢复滚动位置与来源焦点 |
| 本周 / 全部 | 改变队列范围，不改变当前任务 |
| 项目区 | 筛选队列；再点一次取消 |
| 主操作 | 打开提交单；确认后写入页内状态并显示回执 |
| 浅色 | 切换场地与纸面主题；控制台保持墨色 |
| 键盘 | Tab 移动，Enter 打开，Esc 关闭提交单或回执；焦点返回触发控件 |

## 选择性复用了 DCL 的什么

- **状态分层。** 执行阶段、依赖、人工阻塞、查看位置分开；承诺层级独立于执行阶段。方法来自 [状态方案](../state-study/state-model.md) 与 [DCL 状态研究](../state-study/index.html)。
- **守卫与完整性。** 前置满足才可推进；完成记录递归校验；完成、重开、阻塞、解除都留记录。规则来自 R01/R02/R04/R05/R06/R08/R09，见 [规则卡](../../../standards/interface-capability/rules.json)。
- **评审方法。** 行为契约 + 校验器、浏览器轨迹、源码哈希、屏宽与主题组合，沿用 DCL 的证据要求。
- **不复用。** 旧工作台的三栏布局、组件样式、队列行与右侧面板结构都没有沿用；本次重新组织空间与操作顺序。

## 限制

- 真实数据、持久化、revision 并发保护、审计与补偿撤销未接入；页面状态只在内存里，刷新即重置。
- 9 条任务是合成快照，日期与产出是演示数据，不宣称是用户当前的完整工作状态。
- 已完成、进行中、可推进、等待、阻塞、想法六种状态只做了浏览器检查与 Agent 自评；没有真人使用、屏幕阅读器、真机触控与长期使用数据。
- 项目、资料、记录三个一级入口没有展开为完整页面；本稿只重塑「工作」入口，项目带和任务记录是它们的入口。
- 字体复用 [Saira 与 OFL 许可](../prototypes/assets/Saira-OFL.txt)；未新增图片素材，纹理、轨道与切角都由 CSS 生成。
- 本稿是设计样张，不是生产 UI，也没有因此批准替换产品页面。
