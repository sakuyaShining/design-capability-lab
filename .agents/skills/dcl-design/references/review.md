# Quality evidence

Record the skill version, product revision, input fixture, entry point, check commands and outcome. For a regression, keep the same task, data and viewport so the results are comparable.

## Automated or observed browser checks

| Check | Evidence |
| --- | --- |
| Primary task and important refusal or recovery | Action sequence, observable result, and project test or trace |
| State and focus continuity | Expected and observed state, keyboard target after navigation and dismissal |
| Layout and accessibility | Viewports, overflow or clipped content checks, accessible names and actual keyboard path |
| Motion when relevant | Repeated or reversed input, reduced motion, final state |

## Human review

Give the reviewer the task, runnable entry, representative screenshots, and any relevant motion capture. Have them attempt the task without being told the solution. Record pass, revision needed, or unreviewed for each dimension, with the observed screen or action.

- **Wayfinding and comprehension.** Can the reviewer identify the current object, its status and their next action?
- **Recovery and trust.** Can they predict consequences, explain a refusal, and recover without losing work?
- **Visual quality.** Do composition, type, density and surface changes make the intended hierarchy clear and maintain a coherent art direction?
- **Originality and fit.** Does the solution serve this product's objects and workflow? Where does the visual treatment add value, and where does it obstruct the task?

Keep Agent observations and human results attributed separately. Compare version changes against a prior working task and a different product brief.
