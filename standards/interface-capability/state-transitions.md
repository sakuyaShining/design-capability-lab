# 基于状态转移的 UI 设计规范

2026-11-11 · 0.1 候选规范。适用于有任务上下文、前置条件和显式修改的工作界面。本页结合 v0.1 本地任务样例验证，复用时应从新产品的数据语义和实际工作目标推导条件。v0.2 总控台业务提案中的新增规则待审阅与试验。[总控台任务方案](../../examples/task-state/state-model.md)

## 从规则到界面

1. 为每个动作写清**当前条件、触发、检查、结果、拒绝原因和恢复入口**。通过检查后，控件显示具体动作。条件不足时，就地解释缺什么，并呈现当前有用的查看或恢复入口。
2. 把**所在位置、实际进度与当前限制**落实到稳定区域。标题和路径定位对象，阶段条标记进度，紧接标题的提示区解释当前条件与主动作。浏览切换时标题和操作同步更新，依赖关系保留原始方向。
3. 用**位置、面积、文字和色彩共同引导**。主动作放在状态说明旁。待处理内容使用展开的工作面，已处理内容以紧凑记录回看。仅当数据有真实顺序或优先级时，才将某个并列条目放大为首选。
4. 有业务后果的修改，在确认前显示对象、拟变化和相关影响。取消回到原触发点。确认成功后更新阶段与条件，在同一工作区给出结果和可用恢复入口。校验失败把理由放到相关字段，并保留输入。
5. 每个显著视觉属性都应可重建。颜色来自语义变量，间距、字级和组件来自固定布局规则。色彩与文字同时表达含义。插图与图标的制作可另行评估，当前样例以文本和 CSS 完成全部引导。

## 本轮应用

| 画面区域 | 固定职责 | 状态变化时 |
| --- | --- | --- |
| 深色任务栏与路径 | 当前对象及返回位置 | 更新选中项。小屏可折叠任务栏。 |
| 白色任务面与阶段条 | 对象身份和实际执行阶段 | 查看新对象时移动焦点。未知阶段直接写明。 |
| 主提示区 | 当前限制和下一步 | 蓝色引导查看或执行，琥珀色标识异常和人工阻塞，完成回执使用低饱和绿色。 |
| 直接前置与次要资料 | 核对可执行条件及计划产出 | 待满足条目保持可见。已满足组可展开。计划产出不替代实际完成依据。 |

底色 `#eef1f5`、任务面 `#ffffff`、导航 `#18263b`、操作 `#244aaf` 是本次样例的设计选择。新任务复用语义职责，具体色值可由产品设计调整。样例使用现有本地字体和确定性 CSS，无图片请求。

## 使用的三份 Skill 方法

- 依照 Product Design and UX 的任务与状态模型，补齐前置检查、旧记录恢复、取消与重开影响。先写转换条件再选择界面表达。[状态模型参考](https://raw.githubusercontent.com/magnus919/agent-skills/main/product-design-and-ux/references/task-flows-and-state-models.md)
- 依照 Anthropic Frontend Design 的构图方法，让任务标题、执行阶段和当前可用动作支配首屏。用区段、字体尺度、明暗和密度分工建立层次。[Frontend Design 原文](https://github.com/anthropics/skills/tree/main/skills/frontend-design)
- 参照 Vercel 指南检查语义控件、键盘焦点、原生对话框、错误提示和小屏溢出。五档宽度与主要交互已复测，屏幕阅读器和实际业务流程待实测。[Web Interface Guidelines](https://github.com/vercel-labs/web-interface-guidelines/blob/main/command.md)
