交给执行会话的输入为选定版本的 Skill 目录、独立产品需求、目标工作区及其正常运行环境。用新的会话和独立目录启动，避免继续旧对话或加载 DCL 研究目录。人工评审可额外使用本页判据。验收时留存模型、Skill 版本或提交、产品代码版本、启动方式、测试命令和结果。

| 条件 | 通过证据 |
| --- | --- |
| 新会话不依赖之前的聊天记录 | 从新会话提供的输入即可开始。执行记录能追溯关键判断到需求、项目源码或随包资源。 |
| 不需要重新解释基础设计方法 | 输入只提供产品约束、目标和必要偏好。无需追加设计方法教学，即可交付任务、行为、交互和视觉决策。 |
| 能处理与训练案例不同的产品需求 | 新产品拥有不同的核心对象和操作逻辑。实现及说明体现从新需求推导的信息结构与交互。 |
| 产物包含真实可操作的交互 | 有可运行入口。主流程和一个有意义的拒绝或恢复分支可操作，状态变化能在浏览器中复现。 |
| 具备自动化和人工质量评估 | 自动检查留下可复现的命令与结果。真人按指定任务试用，记录导视、交互连续性、视觉层次和原创性的判断。 |
| 知识跨项目复用，并通过版本迭代改进 | 两个不同产品留下使用记录。一次版本改动关联具体失败、对照结果和既有任务回归；运行条件与版本可重建。 |

## 首次迁移任务

只将下面的产品需求交给执行会话，连同选定版本的 Skill 和独立工作区。

> 为编辑团队设计并实现一个本地运行的播客转录校对台。编辑需要从一段样本转录中定位低置信度片段，在原句和改稿间核对，保存草稿，最终确认发布。存在未解决标记时应阻止发布，并让编辑找到对应片段。提供可复现的样本数据。至少覆盖桌面和窄屏。

评审人检查编辑能否找到目标片段、区分原句与改稿、判断草稿与发布的区别、在发布受阻后保留修改并恢复工作。记录完成情况、走错的位置及画面证据。总控台作为已有任务的回归参考，运行其状态实验检查。需要证明 Skill 本身的增益时，可让同一模型在相同产品任务和工具条件下分别使用基线与候选版本，按同一份判据评审。

## 0.2.0 增量评估

跨对象设计在[研究对照](../cases/cross-object-changes/case.md)和 [R10](../standards/interface-capability/rules.json)中有出处。0.2.0 要求在适用场景核对来源对象、目标对象、关联和恢复结果。随包示例使用虚构照片选片清单，覆盖取消、完成、重复意图和回执丢失后核对结果。[随包示例](../.agents/skills/dcl-design/references/linked-record-operation.json)

工程回归运行 `python -m unittest discover -s tests`。评估版本增益时，固定模型、任务描述、项目初始状态和浏览器环境，让独立会话分别使用 0.1.0 与 0.2.0。评审使用相同输入，实际执行主流程和故障分支，记录是否能定位结果、是否保留应保留的对象、重试后对象数是否正确。事实须从运行产物采集，并记录人工对导视与恢复入口的评价。

2026-11-12 工程自测通过。8 项回归覆盖旧版状态轨迹、新版状态与事实轨迹、重复目标、错误关联、缺失字段、布尔值误作计数与非法契约。将 Skill 单独复制到另一目录后，四个合成场景可执行，且成功状态下重复创建会被 CLI 拒绝。总控台既有 v0.1 小样的浏览器回归通过。

脚本自测和研究对照仅支持候选规则。新会话的端到端增益、真人评价和跨产品通过情况仍待试验。
